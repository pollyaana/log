# tlc — библиотека минимаксной log-чебышевской аппроксимации и стенд сравнения

Библиотека на C++17 без внешних зависимостей для решения многокритериальных задач
оценки альтернатив на основе парных сравнений методом минимаксной log-чебышевской
аппроксимации (тропическая математика, Кривулин и др., КИО, 2020, №2, с. 27–58), а также
стенд, на котором та же задача прогоняется через библиотеку и через два аналога
с замером времени, памяти, точности и профиля по строкам.

```
include/tlc/        tropical.hpp (max-алгебра), solver.hpp (метод), problem_io.hpp (формат входа)
src/                реализация (~850 строк вместе с заголовками)
apps/tlc_cli.cpp    утилита: solve / kernels / bench / gen
tests/              модульные тесты на контрольных примерах статьи (§4–6)
fuzz/               фаззер: дифференциальные и метаморфные проверки + вход для libFuzzer
bench/              бенчмарк ядер λ + звезда Клини с учётом памяти
analogs/            исправленные исходники аналогов + адаптеры к общему формату ввода
data/               6 контрольных задач из статьи
scripts/            run_stand.sh (весь стенд), compare_kernels.py, plot_results.py
docs/               algorithm.tex (постановка, псевдокод в окружении algorithm), refs.bib
results/            результаты последнего прогона стенда
```

## Установка и запуск

Нужны только `g++ ≥ 9` (или clang) и `cmake ≥ 3.16`; для профиля — `valgrind`, для графиков — `python3 + matplotlib`.

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build -j
cd build && ctest                                   # модульные тесты + короткий фаззинг
./build/tlc solve data/task1_saaty_hu_p124.txt      # задача с картинки (§4.1)
./build/tlc solve data/task1_saaty_hu_p124.txt --trace   # пошаговый протокол (для раздаточного материала)
./scripts/run_stand.sh                              # весь стенд -> results/
```

Сборка с санитайзерами: `-DTLC_SANITIZE=ON`; libFuzzer (clang): `-DTLC_LIBFUZZER=ON`; gprof: `-DTLC_PROFILE=ON`.

### Формат входных данных (общий для библиотеки и обоих аналогов)

```
name task1
criteria 4          # m
alternatives 4      # n
C                   # m*m чисел; дроби 1/4, десятичные 2.5
1 4 2 2  1/4 1 1/3 1/4  1/2 3 1 3  1/2 4 1/3 1
A ...               # n*n чисел, повторить m раз (A1..Am)
```

Парсер (`include/tlc/problem_io.hpp`, header-only) проверяет положительность, размеры,
число матриц и предупреждает о нарушении обратной симметричности. Дроби хранятся
точно (`num/den`) — это нужно аналогу 2, где элементы строятся как `StructA(num, den)`.

## Что сделано и что получилось

### 1. Верификация на контрольных примерах статьи

Все 6 задач из статьи решены, результаты зафиксированы в `tests/test_main.cpp`
(16 649 проверок, в т.ч. под ASan+UBSan).

| Задача | Совпадение со статьёй |
|---|---|
| §4.1 Saaty–Hu, с.124 (картинка) | полностью: λ=2^{2/3}, (λ⁻¹C)*, w₁, w₂, μ=2√3, ν=2^{11/6}, оба наилучших и оба наихудших вектора; AHP и GM до 4 знаков |
| §4.2 Saaty–Hu, с.122 | полностью |
| §5.1 место работы | полностью (оба w₁, оба w₂, x₁, оба x₂) |
| §5.2 место жительства | λ, GM, порядки — да; **численные расхождения, см. ниже** |
| §6.1–6.2 Belton–Gear | полностью, включая смену рангов в AHP при добавлении копии A2 |

**Расхождения с текстом статьи (§5.2)** — проверены независимо (NumPy):

- *AHP*: статья даёт x ≈ (0.1757, 0.2483, 0.4598, 0.1162); из приведённых в статье матриц
  получается (0.2291, 0.2748, 0.3852, 0.1110). Порядок A3 ≻ A2 ≻ A1 ≻ A4 совпадает.
  GM при этом совпадает до 4 знаков, т.е. данные введены верно.
- *Наилучшие векторы рейтингов*: для двух разных B (по двум векторам весов) в статье
  использован один символ μ, хотя спектральные радиусы разные (5.49 и ≈6.93). Из-за этого
  символьная запись (1, 3/8, 3/μ, 2λ/5μ) не совпадает с приведённым числом 0.4330
  (3/5.49 = 0.5464), и два разных вектора слиты в один. Библиотека выдаёт 4 вектора;
  все дают порядок A1 ≻ A3 ≻ A2 ≻ A4, как в статье.
- *Наихудшие векторы*: вектор (1, 0.866, 1, 0.75) из статьи тропически выражается через
  остальные найденные и отбрасывается, а (1, ν/8, 1, ν/9) ≈ (1, 0.686, 1, 0.61), полученный
  в самой статье на промежуточном шаге, — независим и остаётся.

### 2. Аналоги: найденные проблемы и исправления

**Аналог 1** (`DecisionModel`, GUI на Qt; `analogs/analog1_decision_model/`, патч — `decision_model.patch`):

| # | Проблема | Последствие |
|---|---|---|
| A1-1 | `removeCriteria` не удаляет элемент из `alternativesCompsIsInit_`, а матрицы альтернатив удаляет только если все инициализированы | после удаления критерия модель навсегда считается неготовой; матрицы «съезжают» на чужие критерии |
| A1-2 | `removeAlternative`: `.at(i)` по вектору другой длины, индекс не проверяется | `std::out_of_range` / UB |
| A1-3 | `std::stringstream` без `#include <sstream>` | компилируется только транзитивно |
| A1-4 | `compsIsInitAt`: сравнение `int` с `size_t`, отрицательный индекс | ложный `true`/чтение вне границ |
| A1-5 | нет проверки размеров матриц в сеттерах | падение глубоко внутри метода |
| A1-6 | `tropicalResult()` возвращает **один** наихудший вектор | в задаче §4.1 их два — проверить по исходнику `tropical_decision_method` |

Добавлен `headless_cli.cpp` — консольный вход без GUI: `analog1_cli solve|bench <file>`.

**Аналог 2** (`cli.cpp`, MaxAlgebraA/B поверх Eigen; `analogs/analog2_maxalgebra_cli/`, патч — `cli.patch`):
добавлены режимы `kernels <file>` (вывод в том же формате, что `tlc kernels`, сверка — `scripts/compare_kernels.py`)
и `time <file> <reps>`; исправлены: лишнее умножение в `Kleene`, `std::clock` и единичный замер
(теперь `steady_clock`, медиана, прогрев), отсутствие seed, вырожденный цикл по `m`; добавлен режим
`--shared` (одна серия степеней на λ и звезду).

> Исходники Eigen, Qt, `struct_a.h`/`struct_b.h` и остальных файлов аналога 1 в этой среде
> отсутствуют, поэтому адаптеры аналогов **здесь не собирались**. Единственная точка,
> зависящая от неизвестного API, — `to_double()` в `cli.cpp`. Сборка: `cmake -DTLC_BUILD_ANALOGS=ON
> -DANALOG1_DIR=... -DANALOG2_DIR=...`, после чего `run_stand.sh` подхватит их автоматически.
> Для замеров ниже алгоритм аналога 2 перенесён в библиотеку один-в-один
> (`spectral_radius_naive`, `kleene_star_naive`: те же циклы и то же число умножений).

### 3. Узкие места (профиль callgrind по строкам)

**Аналог 2, n = 60:** 78% всех инструкций — одна строка внутреннего цикла тропического
умножения матриц; оно вызывается 118 раз за прогон: 59 раз для спектрального радиуса
(степени A², …, Aⁿ) и ещё 59 раз — **заново те же степени** для звезды Клини.
Итог — O(n⁴) и двойная работа. Кроме того, в линейной шкале элементы Aⁿ растут как mⁿ:
при m = 100 начиная с n ≈ 155 `double` переполняется и λ = inf (при целочисленных дробях
в `StructA` — гораздо раньше).

**Собственная библиотека, версия 1:** профиль полного конвейера на n = 80 показал, что 89%
времени уходит в `independent_columns`, из них 62% — копирование `std::vector<std::vector<double>>`
(для каждой проверки заново собирался вектор «остальных» столбцов) и 19% — аллокации.
В версии 2 — плоский буфер и маска живых столбцов, без выделений памяти в цикле.

### 4. Решения в tlc

| Операция | Аналог 2 | tlc |
|---|---|---|
| λ(A) | n−1 умножений матриц, O(n⁴), линейная шкала | алгоритм Карпа на log-весах, O(n³), без переполнения |
| (λ⁻¹A)* | ещё n умножений, O(n⁴) | Флойд–Уоршелл в (max, ×), O(n³) |
| P(I ⊕ P⁻ₗₖP) | — | столбец j = pⱼ ⊕ (pₗⱼ/pₗₖ)pₖ, без матричных произведений |
| линейная зависимость | (в статье — «вычеркнуть зависимые») | точный критерий P(b⁻P)⁻ = b |

Точность λ относительно эталона (Карп в `long double`): у обоих ≤ 2·10⁻¹⁴ там, где аналог
не переполняется (у аналога ошибка немного меньше — ~10⁻¹⁶ против ~10⁻¹⁵ из-за exp/log);
звёзды совпадают с точностью ≤ 7·10⁻¹⁴. График — `results/kernels.png`.

Полный конвейер (`results/pipeline.csv`, m = 5 критериев, случайные матрицы шкалы Саати):
на n = 80 — 239 мс с ядрами аналога → 54.8 мс (tlc v1) → 42.2 мс (tlc v2). Оставшееся время
определяется размером ответа: у B на n = 80 74 порождающих столбца и 238 наилучших
дифференцирующих векторов — неединственность решения быстро растёт с n, это свойство метода.

### 6. Тестирование

- `tests/` — контрольные примеры статьи, свойства примитивов, некорректный ввод, совпадение быстрых и наивных ядер на 300 случайных матрицах.
- `fuzz/` — на случайных (в т.ч. вырожденных и необратно-симметричных) матрицах проверяются: λ_Карп = λ_наивн.; звезда FW = сумма степеней; каждый найденный вектор оптимален (ошибка = λ); наилучшие/наихудшие векторы лежат в множестве решений и действительно максимизируют/минимизируют max/min; перестановка альтернатив переставляет ответ. 50 000 итераций под ASan+UBSan — 0 сбоев. Проверено мутационно: при внесении ошибки в Карпа или в формулу (4) фаззер даёт тысячи сбоев.
